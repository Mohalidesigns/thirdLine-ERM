## RCSA-01 — Scores not computed on rapid successive saves (HIGH)

**Where:** `/risk/rcsa/assessments/{id}` (seen in Guided view; same autosave path likely used by Grid).

**Repro**
1. Open an in-progress assessment, switch to **Guided**.
2. Within ~1 second, set Likelihood = 4, Impact = 4, Control effectiveness = Partially Achieved.
3. Reload the page.

**Actual**
- All three values persist (progress counts the risk as assessed).
- `INHERENT` and `RESIDUAL` columns show "—"; treatment is "—".
- The "Before this can be submitted" panel reports **nothing outstanding**, even though this risk is above appetite and has no plan → assessment could be submitted without a mandatory treatment plan.
- The heat map in the side panel *does* show 16 (client-computed), so UI and server disagree.

**Expected:** inherent, residual and treatment are always derived from the latest stored L, I and CE, regardless of save order/timing. The appetite gate must never pass a risk with missing scores.

**Evidence it is a race:** the same inputs entered with ~2 s between fields computed correctly every time (Treasury, IT, Operations). Re-saving one field on the broken row recomputed it (16 / 8 / mitigate).

**Likely cause:** each field triggers its own autosave request; concurrent requests compute scores from a stale row snapshot (read-modify-write), and the last writer stores null scores. Alternatively, computation happens only in the request that changes a particular field.

**Fix direction**
- Server: compute inherent/residual/treatment inside the save, from the **merged final row** (after applying the patch), within a transaction with a row lock (`lockForUpdate`) — or compute in a model `saving` hook so every write path recalculates.
- Client: serialise autosaves per row (queue/debounce, or send the full row state instead of single fields).
- Submission gate: treat any row with L, I and CE present but missing inherent/residual as **not ready**, and recompute server-side on submit before validating appetite.
- One-off: data fix command/migration to recompute scores for all assessment lines where L, I, CE are set and scores are null.

**Acceptance criteria / tests**
- Feature test: fire three concurrent/sequential partial updates (L, I, CE) in any order → stored inherent = L×I, residual = inherent × factor(CE), treatment set.
- Feature test: submit endpoint rejects an assessment containing an above-appetite line with no plan, even if scores were null before submit.
- UI: rapid selection in Guided and Grid both show inherent/residual after reload.

## RCSA-02 — Two RCSA data models; legacy pages show stale data (HIGH)

**Where:** `/risk/rcsa/dashboard` and `/risk/rcsa/matrix` (legacy) vs `/risk/rcsa/dashboards` (cycle-based, correct).

**Actual**
- Legacy Dashboard shows 21 assessments, 100% completion, top risks from the risk register (e.g. "Elevated NPL ratio…"). **Operations and IT show 0%** although both submitted in RCSA 2026 H2. None of the 6 cycle risks appear.
- Risk-Control Matrix lists register controls CTL-001…CTL-010 only; universe risks/controls are absent.
- The legacy **Worksheet** files into a "current open RCSA campaign" — unclear whether that is the same entity as a Cycle.
- Two sidebar items both called "Dashboard"/"RCSA Dashboard" confuse users.

**[DECISION] for product owner** — pick one:
1. Retire legacy Dashboard/Matrix/Worksheet and point the menu to cycle-based pages; or
2. Re-source legacy pages from the cycle/universe tables; or
3. Keep both but label legacy clearly ("Register RCSA (legacy)").

**Acceptance criteria:** one source of truth for RCSA status; completion per unit on every RCSA page matches the cycle detail page; menu shows a single dashboard entry.

## RCSA-03 — ORM queue hides own submissions; raw 403 (MEDIUM)

**Repro:** submit an assessment as user A, then open `/risk/rcsa/review` as user A.

**Actual:** Waiting = 0, table empty ("Nothing is waiting for review"). `/risk/rcsa/review/1` → bare Laravel-style "403 THIS ACTION IS UNAUTHORIZED." page. Assessment page says "It is with somebody else for a decision."

**Expected:** Segregation of duties is correct to keep, but:
- Queue should list own filings as read-only rows with a badge "Filed by you — needs another reviewer", or the counters should explain the exclusion.
- Unauthorised review access should render a friendly in-app page explaining SoD, with a link back.

**Tests:** policy test (submitter cannot review own assessment — keep); feature test that the queue response includes own filings flagged non-actionable; 403 renders the app's error component.

## RCSA-07 — Residual rounding inconsistent (LOW)

BU-RT-R2 residual displays **3.8** in the assessment grid but **3.75** on the cycle dashboard; Treasury shows **2.25** in both. Use one formatter everywhere (suggest 2 dp, trimmed trailing zeros).

## RCSA-08 — Pluralisation (LOW)

"Submitted for ORM review. **1 risks are locked**…", dashboard "**1 risks**". Use a pluralisation helper (`Str::plural` / `trans_choice` / i18n).

## RCSA-09 — Lowercase option labels (LOW)

Control Type (`preventive`, `detective`…) and Frequency (`continuous`, `daily`, `ad hoc`…) in Add Risk → Controls, and state filters in Cycles/Assessments/Action plans (`draft`, `open`, `in review`). Keep enum values; render title-case labels.

## RCSA-10 — View mode not persisted (LOW)

Choosing **Guided** resets to **Grid** after reload/navigation. Persist per user (localStorage or user preference).

## RCSA-11 — Horizontal overflow (LOW)

At ~1080 px wide the assessment grid scrolls horizontally, and after `scrollIntoView` on a row button the whole main pane shifts left under the sidebar. Action-plans "What will be done" column wraps to one word per line. Constrain overflow to the table container (`overflow-x-auto` on wrapper, `min-w-0` on flex parents), give the description column a sensible min-width, and consider sticky first column.

## RCSA-12 — Esc closes drawer while a select is open (LOW)

In Add Risk, pressing Esc to dismiss an open native select closes the whole drawer and discards input. Ignore Esc when focus is inside a form control, or prompt "Discard unsaved risk?" if the form is dirty.

## RCSA-13 — BU name looks clickable (LOW)

`/risk/rcsa/assessments`: business-unit name is styled as a link but only the eye icon navigates. Make the whole row (or the name) a link.

## RCSA-14 — `/risk/rcsa` 404 (LOW)

Redirect `/risk/rcsa` to the RCSA landing (cycle dashboard).
