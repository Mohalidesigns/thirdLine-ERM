The headline. The platform work was real and large — tenancy kernel, full route authorization, REST API + OpenAPI + MCP, queues, workflow v2 with genuine gateways and SLA escalation, an effective-dated measure engine, config bundles that promote dev→prod. That is more platform than most Series-A GRC products carry. The blocker is not missing features — it is numbers on the screen that nothing computed, an architecture story with no screen to point at, and a demo loop that does not close.

Build list for approval — Waves 0–3 ≈ 39 engineer-days

Wave 0 — Integrity. Nothing ships to a customer before this.11 d
  • Purge every fabricated figure. A 15.2% Capital Adequacy tile renders in green next to the controller's own honest line "No ICAAP assessment is on record." board.blade.php:51
  • Rewrite ICAAP. Compute CAR from qualifying capital ÷ RWA. Stop relabelling Pillar 2A as Pillar 1. Stop decomposing Pillar 2 with invented constants. Read the minimum from the tenant — CBN requires 15%, not 10%, for international banks and D-SIBs.
  • Drop the GAUSSIAN_COPULA default. It is the schema default, it is exported into the customer's CSV, and the engine sums scenarios independently.
  • Compute real CVaR; fix the VaR/percentile dual estimator; fix the lognormal μ (missing −σ²/2 — every scenario runs 1.65–3.08× hot); fix the 4.29σ tail truncation.
  • Delete the synthetic "correlation analysis" the code itself labels synthetic; relabel the "tornado".
  • Extend the anti-fabrication CI guard to catch hardcoded constants. It greps for RNG calls only — every fabrication above passes it cleanly. This is the fix that prevents recurrence.
  • Rewrite "NDPA Certified" and "CBN ORMS Compliant" to defensible wording.
Wave 1 — Security blockers a bank's review will fail7 d
  • MFA rebuild. verifyMfa() never calls Auth::login, so an enrolled user cannot sign in at all. The TOTP counter is 4 bytes where RFC 6238 requires 8 — no authenticator app can ever match. The shared secret is sent to api.qrserver.com and rendered as an <img>.
  • Move control-test evidence and data imports off the public disk — they are readable at /storage/… with no session.
  • MIME and size restriction on the loss-event upload (currently any type, 20 MB, file_type taken from the client).
  • Rate-limit the auth surface — there is no throttle anywhere in routes/web.php.
  • Wire node-scoped authorization. visibleTo() is built, tested, and called from nowhere — a branch-pinned user sees the whole organisation. This is the delegated-visibility model a banking group buys the product for.
Wave 2 — Give the architecture story a screen11 d
  • Restore Business HQ and the dashboard builder. Two days recovers ~6,450 lines, 21 widget resolvers and the only graph-edge visualisation in the product. All four competitors open their demo on a dashboard designer; we currently have none.
  • Administration nav block for all 8 builder surfaces — today they are routed, functional, and linked from nowhere, and a CRO opens an empty menu.
  • Permission-gate the sidebar; add branded 403/404/500 pages (one click currently yields an unstyled Symfony "Forbidden").
  • <x-dynamic-detail> on the show pages — a field added in the builder currently appears on create/edit and then nowhere.
  • Generic create/index for tenant-defined object types; observer so object_relationships stays live during a demo instead of freezing at migration time.
  • Render the register scales and heat map from ScoringProfile instead of a hardcoded 5×5.
Wave 3 — Close the demo loop10 d
  • Notifications rebuild. A KRI breach notifies nobody. All domain-event notifications are silently dropped on a real queue (the listener derives its recipient from auth()->id(), which is null on a worker).
  • RCSA launch notifies assignees and appears in My Responsibilities — today a campaign launched on stage is invisible.
  • Completing a treatment plan actually moves the score (the listener guards on a column that does not exist).
  • Fix the nightly treatments:check-overdue crash; fix the escalation ladder that dies at level 1.
  • Stop control edits silently overwriting board-approved residual scores with a differently-computed number.
  • Custom Report Builder honours the options it offers (all four report types currently produce the identical file).
  • Gate the four "AI Risk Statement Builder" panels that error on click; retire the permanently-empty second approvals queue.
Wave 4 — One differentiator that lands. Choose one.8–15 d
  • 4C — Regulator-ready output (recommended first, ~8 d). Route the CBN ORMS, Basel and NFIU exports through the existing document renderer to XLSX/PDF instead of bare CSV — headers and rows are already built. Add scheduled board-pack distribution and server-rendered charts. Every demo should end with "and here is the return you file."
  • 4A — Regulatory obligation register (recommended second, ~15 d). Versioned, effective-dated, clause-level obligations with citations and review dates, per-org configurable thresholds, seeded with real CBN / NFIU / NDIC / EFCC / BOFIA / PenCom / NAICOM clauses. Converts the claimed moat into a demonstrable one. No international vendor will ever build this.
  • 4B — Loss data → capital engine (~12 d). Fit frequency and severity from the loss register instead of hand-typed form fields; genuine Basel L1/L2/L3 capture. Makes the operational-risk story real and directly serves ICAAP.
